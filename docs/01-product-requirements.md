# 產品需求與權限

## 產品定位與範圍

Chainseabase 是約 30 人使用的公司內部需求與回饋管理平台，單一組織、多產品。團隊使用後台管理，外部測試者經 Email 邀請後可在受邀產品前台互動；未登入或未受邀帳號不能讀取公司內容。

第一版包含 Google 登入、Email 邀請、Feedback、公開 Roadmap、Schedule【新功能】、單維度 Roadmap 拖曳【新功能】、Personal【新功能】、成員權限【新功能】、站內通知、標籤設定，以及產品 Google Calendar 讀寫。

不包含多組織 SaaS、計費、產品封存／刪除、Feedback 附件、回饋合併、訂閱寄信、甘特圖、Schedule 自動轉日曆、Calendar 參與者邀請與 Google Meet。

## 名詞與範圍

| 名詞 | 定義 |
| --- | --- |
| Product | 產品資料的最高業務範圍。Feedback、分類、Person tag、Roadmap、Personal、通知及日曆綁定屬於產品。 |
| 團隊成員 | 組織層級角色，可管理所有產品與共用資料，但不能查看其他人的私人 Personal／個人 Tag／OAuth 憑證。 |
| 測試成員 | 組織帳號，只能在受邀產品前台互動；不能進後台。 |
| 狀態／類別 | 每筆 Feedback 各有一個值，產品內獨立管理。 |
| Tag | 一般標籤，可無群組或屬單選／複選群組。 |
| 版本 | 產品內專用單選 Tag 群組的呈現，不是第二套獨立版本資料。 |
| Person tag | 工作職掌，可多選，例如 UIUX、前端、後端；與一般 Tag 分開。 |
| 個人 Tag | 依產品與擁有者隔離，只能本人建立、查看、編輯。 |
| Roadmap | 產品共用看板，依一個狀態、類別或單選 Tag 群組維度分欄。 |
| Personal | 本人的整理空間；可切換要查看的負責人，但整理結果仍屬本人。 |

產品切換後，所有產品相關資料與表單必須切換。帳號名稱、頭像與組織角色為共用資料，不因切換產品改變。

## 導覽與路由

後台側邊欄依序固定為：

1. Product
2. Feedback
3. Roadmap
4. Personal
5. Live Portal
6. User
7. Notification
8. Setting

後台預設開啟 Product。Live Portal 是跨站導覽，預設在目前分頁前往相同產品的獨立前台；支援瀏覽器開新分頁。前台不顯示後台導覽。

建議後台路由 `/products/:productId/{dashboard,feedback,roadmaps,personal,users,settings}`；Notification 以浮層呈現，不跳頁。前台使用獨立網域及 `/p/:productSlug/{feedback,roadmap}`。Feedback 以 Modal 開啟，URL 可用查詢參數保存項目識別，重整／返回可還原，不強制跳頁。

## 角色權限

| 行為 | 未登入／未受邀 Google 帳號 | 測試成員 | 團隊成員 |
| --- | --- | --- | --- |
| 瀏覽已發布前台與前台可見 Feedback／Roadmap | 不可 | 僅受邀產品 | 可 |
| 新增前台 Feedback、投票、一般留言及按讚 | 不可 | 僅受邀產品 | 所有產品 |
| 修改自己的前台 Feedback 標題／描述 | 不可 | 受邀且內容仍公開時可 | 可 |
| 編輯自己的普通留言 | 不可 | 受邀且內容仍公開時可 | 可 |
| 後台新增、編輯、軟刪除共用 Feedback／普通留言 | 不可 | 不可 | 可 |
| 設定可見性、狀態、類別、Tag、Person tag、優先級 | 不可 | 不可 | 可 |
| Schedule、Roadmap 編輯、產品管理與 Setting 管理 | 不可 | 不可 | 可 |
| Personal、個人 Tag | 不可 | 不可 | 僅自己的私人資料 |
| User、邀請、移除、角色變更 | 不可 | 不可 | 可；不可移除／降級最後一位團隊成員 |
| Calendar 讀寫 | 不可 | 不可 | 另需本人 Google 授權與日曆權限 |
| 他人的 Google token、私人 Personal／個人 Tag | 不可 | 不可 | 不可透過產品管理權讀取 |

工程預設：測試成員第一版不提供刪除 Feedback／留言入口；可編輯自己的文字，移除由團隊處理。團隊不得改寫指令留言，須走 Schedule 操作移除流程。

後端必須逐次驗證權限。修改 URL、API ID、產品參數或前端狀態不能繞過限制。

## AUTH：登入與邀請

- Google 為唯一登入方式。以 provider subject 識別帳號，經驗證 Email 用於邀請比對。
- 首位團隊成員由部署初始化指定 Email，不以「第一個登入者」自動取得管理權。
- 團隊透過 Email 邀請團隊成員，或邀請測試成員並指定產品集合。
- 邀請需使用對應 Email 的 Google 帳號接受；未受邀者登入後仍不可讀取公司內容。
- 邀請碼不可猜測，資料庫只存雜湊，單次使用；工程預設 7 天有效，可撤銷及重寄。
- 角色降級不自動取得全部產品的測試資格，需明確指定受邀產品；移除成員時保留其歷史作者識別，撤銷互動與後台存取。
- 團隊降為測試或移除時撤除 Person tag 關係，使 Personal 責任範圍即時更新；保留私人資料但本人無後台權限時不可存取。

## PROD：Product Dashboard

- 初始化建立「產品1」，提供產品新增、重新命名、切換，不提供封存或刪除。
- 產品名稱可修改，穩定產品 ID 不變；工程預設網址 slug 不隨名稱自動改變。
- 初始化每產品的狀態、類別「需求討論」、版本單選群組與預設 Roadmap。
- Dashboard 只呈現產品管理與 Google 日曆，不自行加入 KPI、營收或統計圖。
- 切換產品時關閉或重新建立產品相關 Modal；有未儲存草稿先提示。清除舊產品查詢狀態，拒絕遲到回應覆蓋新畫面。

## FB：Feedback

列表預設依狀態分類，支援類別、Tag 篩選與搜尋。搜尋範圍為目前產品的標題與描述，前台只搜尋公開 Feedback。文字搜尋需支援繁體中文片段，不將只支援英文斷詞的搜尋當成完成。

建立／查看／編輯使用 Modal，保留內容與留言，提供 Schedule Tab，移除 Insight Tab。

| 位置 | 欄位 | 初始值／規則 |
| --- | --- | --- |
| 頂部 | 建立者、頭像、時間 | 系統帶入，不可代填；正式建立時間由伺服器產生。 |
| 內容 | 標題、描述 | 標題必填；描述可空。 |
| 第一排 | 狀態 | 新貼文。 |
| 第一排 | 類別 | 需求討論。 |
| 第一排 | Person tag | 未安排；有實際職掌時可複選。 |
| 第二排 | 優先級 | 非常重要 P0。 |
| 第二排 | 版本 | 未歸類。 |
| 第二排 | ＋標籤 | 加入既有或建立一般 Tag，遵守群組單複選。 |
| 第三排（僅 Personal 情境） | 個人 Tag | 只傳回目前登入者自己的 Tag。 |
| 底部 | 新增多筆 Switch | 預設關閉。 |

後台欄位以 Dropdown 操作。前台不暴露內部分類控制；建立時由後端填入預設值。

工程預設：標題 1–200 字元、描述最多 20,000 字元；優先級 P0 非常重要、P1 重要、P2 一般、P3 低。描述支援基本 Markdown（段落、清單、粗體、連結），禁止原始 HTML；第一版不含圖片／附件上傳。

連續新增成功後保持 Modal，清空標題、描述與整份 Schedule 草稿，保留狀態、類別、Person tag、優先級、版本及一般 Tag，Switch 維持開啟。失敗時不得清空。建立者與時間重新產生。

## TAG：設定與「未安排」

- Setting 固定三個 Tab：個人設定、管理標籤、管理 Person tag。
- 個人設定可修改名稱、頭像與本人在目前產品的 Person tag；頭像上傳為帳號功能，不等於 Feedback 附件功能。
- 管理標籤包含狀態、類別、一般 Tag 與群組；群組決定單選或複選。
- 「版本」群組固定單選且不可移除其系統用途；未選時顯示「未歸類」。
- 「未安排」是 Person tag 的保留預設選項，資料層表示沒有實際職掌關係；不觸發指派通知，不能與實際 Person tag 並存。選「未安排」會清除實際職掌，選實際職掌會取消「未安排」。
- Person tag 可新增與移除，團隊成員與 Feedback 都可多選，同一職掌可由多人持有。
- 刪除被使用的選項前顯示影響，先遷移、解除引用或指定替代值；不能讓必填狀態／類別變空。Roadmap 欄位對應值的移除必須一起處理。
- 複選群組改單選前先解決所有多選衝突；被 Roadmap 使用的單選群組不可直接改複選。

## PORTAL：獨立受邀成員前台

- 前後台是不同網站入口，共用產品與 Feedback 資料；不是在原後台 Modal 內開啟前台。
- 後台建立的 Feedback 預設 `internal`，團隊可發布為 `public`；前台建立的 Feedback 預設 `public`。
- 具該產品資格的登入成員可看前台可見標題、描述、作者公開名稱／頭像、建立時間、狀態、普通留言與投票數。
- 不傳回登入 Email、Person tag、優先級、版本、一般內部 Tag、Schedule、私人資料、內部操作紀錄與日曆。
- 發布為公開的 Feedback，其普通留言也屬公開討論；後台留言框需清楚標示公開範圍。內部工作內容使用 Schedule，不另混入公開留言串。
- 改回內部後，前台列表、搜尋、直接網址、通知連結及相關快取均不可再取得該內容；曾受邀或曾為作者不構成例外。
- 提供 Feedback 投票（每人每筆最多一票，可收回）、普通留言、按讚及引用回覆。
- 工程預設：每張 Roadmap 可選是否發布前台，預設不發布。僅狀態維度看板可發布，避免版本／內部分類欄名洩漏；前台僅顯示公開卡片且不可拖曳。這是公開投影的保守預設，不影響後台所有看板。

## USER：使用者管理

- 目前產品 User 列表包含所有團隊成員與該產品受邀測試成員。
- 顯示頭像、名稱、Email、Person tag、在目前產品建立的 Feedback 數量與入口。
- 團隊成員可管理其他成員角色與移除成員；最後一位團隊成員受保護。
- 個人頁面以「建立的 Feedback／留言」分 Tab，內容限定目前產品；不藉此顯示私人 Tag。
- 使用者頁的留言可標示一般／Schedule 來源，只有團隊後台可看到 Schedule。

## NOTIFY：站內通知

- Feedback 新增實際 Person tag 指派時，通知新取得負責關係的團隊成員，同一事件每人只一筆。
- 有人在自己建立的 Feedback 發表普通留言或 Schedule 留言時，通知建立者；指令留言同樣算一次，不因表格與歷史另產生重複通知。
- 不通知事件操作者本人；同事件符合多種原因合併為一則。已由其他職掌負責的人不因新增第二個同屬職掌而重複收到指派通知。
- 後來取得 Person tag 的成員不追溯通知既有 Feedback，但其 Personal 負責清單會更新。
- 通知必須檢查接收者能否存取內容。測試作者不可收到含內部 Schedule 的通知；移除權限後不可透過舊通知讀取內容。
- 顯示浮層清單、未讀數、標記已讀；點擊可在目前網站開啟允許的 Feedback Modal。通知依目前產品顯示。
- 第一版不寄送通知 Email；Email 僅用於成員邀請。

Schedule、Roadmap、Personal 詳細規則見 [核心互動](03-interaction-rules.md)；日曆見 [Calendar 與部署](06-calendar-and-deployment.md)。
