# 給實作 AI 的指令：Feedback 詳情與留言

請把本包已確認的外觀與互動範圍，套用到目標專案「建立 Feedback 後，點擊清單項目開啟的詳情彈窗」。不要把它還原成新增表單，也不要自行新增後端功能。

## 開始前先讀

1. 目標專案的 AGENTS／README、元件規範、字型與 Design Tokens。
2. 本包的 `STYLE_SPEC.md`、`source/App.tsx`、`source/index.css`。
3. `reference-desktop.png` 與 `reference-mobile.png`。

本包優先於之前的 `feedback-style-kit`／v2 新增表單交接內容；舊包中的「新增 Feedback」、建立者記錄、新增多筆、取消／建立等要求已不適用。

## 技術背景

- 來源：React 19、TypeScript 5.7、Vite 8、Tailwind CSS 4。
- 先前指定的目標：Next.js 16.4.2、React 19.3.1、TypeScript、Tailwind CSS 4、shadcn/ui／Radix UI。
- 來源只直接依賴 React；圖示為 inline SVG，沒有額外圖示套件。
- shadcn Message 用於參考頭像、名稱、訊息內容的分層，不代表來源已安裝該元件。
- 這是元件與樣式快照，不含目標專案的路由、資料層或完整建置設定。

## 必須呈現

1. 詳情標題顯示既有資料的結果，以 `Test` 作示意；描述為唯讀結果，自然撐高，不保留輸入框的固定高度。
2. 移除新增表單標題列及其底線、內容區圖片按鈕、Feedback 建立者／時間、新增多筆、取消／建立按鈕。
3. 保留右上關閉按鈕，以及狀態、類別、Person tag、灰底無框「＋」四顆 32px 膠囊。
4. 下方採精簡留言區，不加 Discussion／Insights 分頁、完整工具列或建立活動記錄。
5. 兩則留言都含頭像、名稱、灰底氣泡、建立時間、按讚計數與回覆圖示。
6. 建立時間位於氣泡緊鄰右側，與氣泡垂直置中，不放在按讚／回覆上方，也不放進氣泡裡。
7. 留言輸入框底部左側為圖片按鈕，右側為圓形送出箭頭。不顯示已刪除的「樣式預覽，留言不會送出或儲存」提示文字。

## 兩則留言的樣式差異必須保留

- 第一則「設計團隊」：按讚後有淡紫底，圖示仍為線框；hover 有淡灰底。
- 第二則「歐瑜」：任何狀態都沒有底色；按讚後圖示實心，取消後恢復線框。
- 這是逐一選取修改後的結果，不要為求一致而把第二則的樣式擴大套用到第一則。
- 兩則按讚初始皆為 0，切換後各自為 1，再次切換回 0，彼此不影響。

## 互動邊界

來源目前保留：

- 屬性膠囊的前端選單切換。
- 關閉／重新開啟預覽。
- 透過原生 checkbox 與 Tailwind peer 樣式實作的本地按讚狀態與 0／1 計數，可用鍵盤操作。

來源目前沒有：

- 留言輸入或送出：textarea 為 readOnly，送出鍵停用。
- 圖片選擇／上傳：圖片按鈕停用。
- 回覆流程：回覆圖示按鈕停用。
- API、登入、跨使用者按讚總數、資料庫或持久儲存。
- 已實作的名片附件；「名片」需求尚未釐清，不要自行加入。

標題、描述、名稱、留言及建立時間都是範例，不是真正查詢資料。前端按讚會在重新整理或留言元件卸載後重設，不是已保存的正式數據。

若目標專案已有正式資料與事件，保留其資料流及功能，僅整合必要外觀；不要用範例資料、原生示範 checkbox 或停用狀態取代正式功能。若沒有正式功能，不要在這次交接中擅自加上，先確認範圍。

## 整合注意事項

1. 保留目標彈窗最外層既有圓角、開關、Portal、focus trap、Esc、overlay 與可及性設定。
2. 不要直接用來源的 section 冒充正式 modal；正式彈窗應沿用目標既有 Dialog。
3. 來源的 `screen`、`closed-state`、body 背景及桌面置中是預覽用，不要套到整個正式應用。
4. `source/index.css` 是完整來源，不是已隔離的元件 CSS；不要直接覆寫目標全域樣式。將元件樣式限制在這個 Feedback 詳情實例內，避免 `.message` 等通用類名影響其他元件。
5. 保留原有 Tailwind CSS 4 入口，不要重複匯入 Tailwind。來源的兩個 `@import` 必須位於來源 CSS 頂部；正式專案優先沿用既有字型，不要重複載入。
6. 來源使用公開 Google Fonts 的 Noto Sans TC，以及 Arial／系統中文字型 fallback；不需要任何私有字型或憑證。
7. 來源有 hooks 與事件；在 Next.js 中須放在既有的 Client Component 邊界內。CSS 從目標既有樣式入口載入，不要為此搬移其他 Server／Client 邊界或升降級套件。
8. 與 shadcn／Radix 整合時，僅解決這個實例的 padding、gap、width、focus 樣式衝突，不改共用元件原始碼。
9. 來源以 inline style 保存部分指定實例的編輯值，會覆蓋共用 CSS；請以最終計算樣式為準，而非只看 CSS 檔。
10. 每次只改使用者指明的實例。若必須修改選取範圍以外的元素，先用非技術用語說明並取得同意。

## 最新對齊設定的解讀

- 兩個指定 article 的 `align-items` 為 `center`。
- 兩個指定氣泡帶有 `align-items: flex-end`、`justify-content: flex-start`、`gap: 8px 12px`、`column-gap: 12px`。
- 目前氣泡本身是 block，且只包含一個段落；上述 flex 對齊與 gap 設定不會改變氣泡與時間的距離。不要誤認為時間間距是 12px。
- 氣泡與時間的排列由外層 flex wrapper 負責，垂直置中、間距 8px。這是已確認的時間位置。
- 若後續需求需要讓氣泡內部變為 flex／grid，請先確認，不要在還原本版本時自行「修正」這些值。
