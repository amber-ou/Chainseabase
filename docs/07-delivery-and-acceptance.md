# 交付階段與驗收案例

## 完成定義與目前狀態

本次交付為需求、架構、互動、API、設計與部署規格。以下測試與實作里程碑均為**待執行**，不是測試報告。沒有應用程式可啟動，不能宣稱功能、OAuth、Calendar 或部署已通過。

每個功能完成需同時具備：對應 API 與資料驗證、權限、完整 UI 狀態、關鍵測試、文件同步，以及可追溯的驗收結果。第三方測試明確區分 mock、sandbox 與正式環境。

## 測試資料

使用隔離環境建立產品甲／乙、兩位團隊甲／乙、一位僅受邀產品甲的測試者，以及一位未受邀 Google 帳號。

- 產品甲建立 UIUX／前端／後端 Person tag；團隊甲與乙可共同持有 UIUX，團隊甲另持前端。
- 建立版本 single 群組（v1.0／v1.1）、用途 multiple 群組（效能／介面）、未分組 Tag。
- 建立公開與內部 Feedback，含沒有 Person tag、同時掛多職掌、未歸類版本與長內容。
- Calendar 使用專用 sandbox 日曆：writer、reader、未被分享使用者各一；包含單次、全天、每週系列、取消／改期例外及外部含與會者活動。
- 測試人物與內容只存在測試資料集，正式初始化不植入示範資料。

## 測試證據格式

每次驗收記錄：commit、環境、日期、資料集、執行命令、實際測試數、passed／failed／skipped／unrun、失敗原因與截圖／報告位置。不要把零測試或 mocked provider 當成端到端成功。

文件變更只需適當的連結、結構、差異與一致性檢查；程式實作完成後才執行對應測試。正式發布前逐項確認外部資源已配置，不以文件寫好取代部署驗證。
