## 永久刪除產品

### 已確認行為與資料範圍

- 所有團隊成員可刪除產品；測試成員與匿名使用者不可。後端必須驗證，不能只隱藏按鈕。
- 採永久刪除，不以軟刪除、封存或僅從清單隱藏替代，介面不提供復原。
- 刪除平台內該產品及其專屬資料：Feedback、留言／Schedule／歷史、Roadmap、Personal 私人整理及私人標籤、分類／版本／Tag／職掌、產品存取與邀請關聯、通知、日曆綁定及本地活動關聯、產品工作與冪等記錄等。依實際 schema 完整盤點外鍵，避免遺留可存取的孤兒資料。
- 不刪除其他產品、共用使用者帳號、組織身分或個人 Google 授權；多產品共用的邀請或工作只移除目標產品關聯，不連帶破壞其他產品。
- 邀請（2026-11-03 使用者確認）：尚未接受的測試成員邀請若因此沒有任何有效產品，在同一交易撤銷並保留撤銷紀錄；仍關聯其他產品者只移除該關聯。已接受的邀請不回溯撤銷，不刪除帳號或其他產品資格。取消尚未送出的邀請信工作；寄送前與接受時都重新檢查邀請與產品關聯。已寄出的信無法收回，連結開啟後顯示「邀請已失效」，不得接受成為沒有產品的測試成員。團隊成員邀請不受影響。
- Google（2026-11-03 使用者確認）：刪除時已送出的 Google 操作可能完成，接受此限制，不以刪除 Google 活動補償；刪除後的新操作與重試必須拒絕，且不可回報平台關聯已儲存。
- 刪除範圍限定在平台內；**不刪除 Google 上的共用日曆與活動**，也不撤銷 Google 分享 ACL。解除的是平台內產品綁定及關聯。
- 允許刪除最後一個產品，包括「產品1」。完成後顯示空清單與「新增產品」，不自動重建預設產品；初始化／seed 必須區分首次初始化與使用者主動刪空。

### 防呆 Modal

從該產品列的刪除操作開啟 Modal，必須具備：

1. 標題「永久刪除產品『{產品名稱}』？」。
2. 明確說明該產品及其平台內所屬資料會永久刪除，無法在平台內復原；Google 上的日曆與活動不受影響。列出受影響資料類型；若展示數量，必須來自實際資料，不能寫死或假造。
3. 欄位標籤「輸入產品名稱以確認」，並清楚顯示須輸入的完整名稱；欄位初始為空，不預填。
4. 只有輸入內容與產品目前的完整名稱完全一致時，才啟用「永久刪除」按鈕。不得僅靠非空、部分比對、大小寫折疊或自動代填通過。
5. 「取消」為安全出口；危險操作不取得預設焦點，不以 Enter 在未通過確認時提交。Modal 有標題語意、焦點管理、鍵盤操作，關閉後回到原入口或合理的清單焦點。
6. 提交時顯示「刪除中…」並防止重複提交；成功前不先移除產品或宣稱成功。失敗保留 Modal、顯示原因及重試方式。
7. 網路逾時不直接判定成功或失敗，先查明產品狀態，避免盲目重送或錯誤成功提示。

名稱確認需在伺服器再次驗證，請求鎖定產品 ID 與目前 revision。若開啟 Modal 後產品被改名或修改，拒絕過期確認並更新資料，要求重新確認；名稱不是識別鍵，也不是授權依據。

### 一致性與刪除後導覽

- 資料庫刪除需具交易一致性，失敗不能留下刪除一半的產品。實作前盤點相關資料、並行寫入、排程與 outbox；刪除期間及完成後不得再為該產品產生通知、寄信或日曆操作。
- 處理已領取／進行中的外部工作；若無法保證所述行為，先向使用者說明限制，不以關閉 UI 假裝完成。
- 成功後刷新清單、側邊欄產品選擇器及相關快取；若刪除目前產品，清除其選取狀態並返回 Product，由使用者選取其他產品。刪除非目前產品時保留原選取。
- 已開啟的產品頁、公開前台、舊網址及直接 API 請求不得再存取已刪資料；呈現產品不存在或不可用，不返回快取的舊內容。
- 清單空白時顯示「尚無產品」及「新增產品」；其他依賴產品的入口應提示先新增／選取產品，不發出無效產品請求。
- 重試或同時刪除同一產品不得誤刪其他產品；重複請求應回應一致的已不存在／已刪除結果。

## 第六階段：登入入口與 Product 視覺（2026-11-05 新增）

### 登入入口（後台）

- 未登入開啟後台首頁或任何 `/products…` 頁，直接進入第五階段的 Login 頁，不再先顯示「請先登入／前往登入」提示頁。仍由使用者點「使用 Google 登入」才前往 Google。
